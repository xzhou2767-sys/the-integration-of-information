# 视频能力方向 A：Agent 观看（证据包模式）工程方案 v2.0

> 版本：2.0｜编制日期：2026-09-18｜状态：设计定稿，待实施（非上线证明）
> 依据：《视频内容提取三方向改进实施方案》1.0（2026-09-18，外部输入）＋ `docs/PROJECT_SYSTEM.md`（决策核心 V2 / P0 修复后现状）
> 取代 v1.0 设计稿。v1 中"证据无损""默认不碰视频流已实现"等不准确陈述按方案 §13 要求删除，本文区分**文本覆盖**与**视觉抽样**两类证据的真实边界。

## 一、目标与非目标

**目标**：Agent 对视频的问答不基于标题臆测，而是基于可检索、可引用、可校验的证据：
1. 返回带 ID 与时间范围的转录片段和帧证据，每项含来源与质量标记；
2. 问答默认只查文本证据（字幕/ASR，零视觉成本）；涉及画面或文本不足时，定位时间窗后**按需取帧**；
3. 回答中的事实引用 `segmentId/frameId`，客户端可跳转原视频时间点；证据不足时显式说明缺口；
4. 文本证据、原始帧、视觉描述**分开保存**，模型生成的描述不冒充原始事实。

**非目标**（本期不做）：配音与人声分离、全片无损视觉覆盖、密集采样长视频、多租户计费、自动成片。
**默认自动流程只覆盖低成本信息提取**；密集视觉分析由明确的 evidence 模式请求触发。

## 二、当前实现（PROJECT_SYSTEM.md 5.6 现状，均为已验证事实）

```
下载(300MB上限,双保险计数) → 字幕优先(跳过ASR) → faster-whisper ASR兜底
→ AI推断关键帧时间戳 → FFmpeg截帧 → OCR(仅详细档)+视觉描述(六级降级链)
→ AI三源融合总结
```

| 环节 | 现状（v2.0 基线） | 证据组织差距 |
|---|---|---|
| 转录 | 字幕优先跳过 ASR（低成本已达成） | segments 无稳定 ID、无 `transcriptSource` 标记 |
| 帧策略 | 三档帧数（模糊 0 / 默认 3 / 详细 5+OCR） | **所有档位先下载完整视频**（B02）；帧默认抽取但无消费者场景不跳过（B03） |
| 帧去重 | 无 | 高密度采样必需（16×16 灰度差方案见 §6） |
| 时间窗 | 无（全片处理） | 无 `startSec/endSec` |
| 输出 | 总结文本 + keyFrames（timestamp/ocrText/description） | 压缩为总结，**无证据包模式**、无 coverage 标记 |
| 任务期限 | **30 分钟总期限已上线**（2026-09-18 P0：`withTimeout` 超时返回受限原因） | 帧数参数硬上限仍缺（B09 部分缓解） |
| 成本 | 模糊档确实零视觉调用（表已兑现） | 无按任务的预算计量与停止条件 |

**决策核心 V2 衔接**（PROJECT_SYSTEM.md 5.9）：视频条目进入 feed 时走统一准入（`AdmissionPolicy`，动态内容 45 天窗，未知日期 NEEDS_EVIDENCE freshness=0.3）→ `DedupService` 身份去重 → `ContentRanker` 排序。方向 A 不改变该链路，只提供视频条目更可靠的内容层证据。

## 三、差距对照（方案 §2 阻断项映射）

| 编号 | 问题 | 对本方向的影响 | 本期动作 |
|---|---|---|---|
| B02 | 所有档位先下载完整视频 | 纯文本问答也要付全片下载成本 | 字幕前置＋音频优先（共享内核，见 §6） |
| B03 | 默认抽帧但无消费者 | 证据包未消费时白付视觉费用 | AnalysisPlanner 按需跳过 |
| B06 | 等待进程退出后才读输出 | 大视频超时前无法观察到进度/卡死 | ProcessRunner 并发消费 stdout/stderr |
| B07 | 字幕时长为 0 / 假定 600 秒 | 证据时间轴失真，引用错位 | 真实时长 + 时间戳校验 |
| B09 | 详细档帧数无可靠上限 | 证据包帧数失控 | 参数上限 + 预算 + 降级 |

## 四、证据包契约

```json
{
  "taskId": "task_01HZX3K7Q2P9W8R4T6Y8V0A1B",
  "sourceId": "source_4523",
  "durationSec": 180,
  "transcriptSource": "asr",
  "segments": [{"id":"seg_1","start":12.3,"end":15.1,"text":"原文","language":"en"}],
  "frames": [{"id":"frame_1","timestamp":14.0,"artifactId":"img_1","segmentIds":["seg_1"]}],
  "coverage": {"requestedStart":0,"requestedEnd":180,"transcriptComplete":true,"visualSampling":"sparse"},
  "warnings": [],
  "cost": {"status":"estimated","currency":"CNY"}
}
```

`transcriptSource` 为单值字段，schema 枚举候选：`platform_caption` | `embedded_caption` | `asr`（上方示例值 `asr` 为合法值，勿把枚举列表当接口数据复制）。

规则：
- 所有时间戳为**原视频绝对秒数**；片段处理保留 `sourceOffsetSec` 防二次偏移（B07）。
- `coverage` 显式标记文本覆盖与视觉抽样范围：`visualSampling: sparse` 表示帧证据是抽样而非全片覆盖，**不得宣称"证据无损"**。
- 证据包不默认内嵌 base64 图像；帧图经任务产物端点（`GET /api/video/tasks/{id}/artifacts/{artifactId}`）按需授权读取，返回有效期与大小。
- 模型取帧建议必须经有限数值/范围/去重/排序/上限校验；无效建议回退**真实范围内均匀取样**，不再假定 600 秒。
- 没有声音但画面有内容的视频：文本模式返回"无可用语音"警告，允许用户显式触发视觉模式。

## 五、接口与错误

复用共享内核任务接口（详见方向 B 文档 §工具契约，`POST /api/video/tasks` 规范化请求）：

- `mode: "evidence"` 进入证据包模式；`fields` 参与依赖计算，仅请求 metadata 时不得启动 ASR/取帧/总结。
- 阶段产物经 `GET /api/video/tasks/{id}/evidence` 分页获取，支持字段筛选。
- 错误结构统一（任务状态 `queued/running/succeeded/partial/failed/cancelled` + 错误码 + 可重试性）；证据不足返回 partial 而非失败。

## 六、共享依赖（三方向共用内核，不重复建设）

| 组件 | 对方向 A 的供给 |
|---|---|
| SourceResolver | 稳定来源 ID + 字幕清单（人工字幕优先于自动字幕，保留语言与来源标签） |
| AnalysisPlanner | 按问题类型决定阶段：文本问题不触发视觉；画面问题才取帧（A2 验收口径） |
| TranscriptService | `transcriptSource` 归一化，不伪造语言与时长 |
| EvidenceService（新增） | 片段/帧/OCR/引用对齐与覆盖范围声明 |
| ArtifactCache | 阶段缓存键 `sourceId+sourceVersion+timeRange+stage+language+modelVersion+promptVersion+paramsHash` |
| BudgetService | 调用前预留预算，不足时返回已完成产物 + `budget_exceeded` |
| ProcessRunner | 子进程 stdout/stderr 并发读取、输出限额、进程树终止 |
| 感知哈希去重 | 16×16 灰度平均绝对差（第一版），保留时间跨度与丢弃计数，防静态画面小文字变化被过度过滤 |

**与决策核心 V2 的衔接点**：视频抓取单元的收益观测沿用 `DecisionStore` 口径（奖励=新增唯一条目数，`identityOf` 身份集合对比），视频来源不另设计量体系；`sourceSchedulerV2` 开启时视频单元按同一 `expectedUseful/cost` 公式排序。

## 七、缓存和费用

- 缓存：阶段级（转录、帧、OCR 分开缓存），非仅最终总结；`forceRefresh` 只旁路对应阶段且仍受预算限制。
- 费用口径：下载字节 + ASR + 文本模型 + 视觉模型 + 重试分项计量；usage 不可得时标"估算"。
- 帧预算：`brief` 0 帧 / `standard` ≤3 / `detailed` ≤8，全局硬上限 12 帧（压测后才可调）；帧尺寸长边默认 ≤768px，局部 OCR 按预算可至 1280px，计量实际像素量而非帧数。
- 对标成本结论（v1 的"成本优势 10-100 倍"表述删除）：以 M0 基线的同集对比为准，目标低成本文本场景总估算成本中位数下降 ≥30% 且质量验收不退化。

## 八、任务清单（映射方案 §9 里程碑）

| 任务 | 内容 | 完成定义 |
|---|---|---|
| A1 | Evidence DTO、EvidenceStore、时间轴关联 | 时间窗与引用 ID 可追踪，源时间不偏移 |
| A2 | 按问题定位片段、受预算限制取图 | 文本问题视觉调用=0；画面问题实际消费图片 |
| A3 | 回答引用校验与不足提示 | 所有返回引用可解析，越界引用被拒绝 |
| A4 | 客户端证据导航及任务状态展示 | 点击引用跳转正确片段；稀疏抽样标记可见 |
| A5 | 质量评估 | ≥30 个有人工参考的问题：事实正确率 ≥90%，引用支持率 ≥95% |

依赖：M2（共享内核）完成后推进 M4；引用支持率按人工逐条核对"被引内容是否支撑该事实"统计。

## 九、验收数据

- 文本问答（有字幕样本）：视频媒体下载字节=0、ASR/取帧/视觉调用=0；
- 画面问题：实际取帧数 ≤ 预算，引用时间戳与原片误差中位 ≤0.5s；
- 长视频末尾独有结论能被回答并附有效证据引用（B07 回归）；
- 相同来源同参数二次请求命中阶段缓存，不重新转录/取图。

## 十、限制（显式声明）

- **当前来源仅 HTTP(S) 媒体直链**（服务端下载器为 `http.get(url)`，尚无平台页解析器）；YouTube/Bilibili 平台页解析为待实现能力（需真实解析与样本验证后开放）——与本方向 §六 SourceResolver 的"首批承诺支持"为**目标态**，实施前不得宣称。
- 登录、DRM、区域限制返回明确错误，**不支持"任意 URL"**。
- 视觉证据是抽样性质（sparse），不能作为全片完整性证明；字幕最后结束时间只代表覆盖范围，不等于视频时长。
- 元数据时长未知时禁止精确剪辑导出，其他能力降级并给出警告。

## 十一、发布与回滚

- 功能开关：`evidenceMode`（沿用 ConfigStore Snapshot + 环境变量 + 默认 false 的灰度模式，同 `decisionCoreV2` 先例）；依赖 `videoPlannerV2` 内核开关。
- 灰度顺序：固定测试样本 → 内部账户 → 少量真实请求 → 全量；比较错误率、P95、费用、队列长度。
- 回滚：关闭 `evidenceMode` 恢复旧 `POST /api/video/analyze` 路径；已有任务保留状态与产物，后台无孤儿任务。
