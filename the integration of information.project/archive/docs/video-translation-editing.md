# 视频能力方向 C：概要翻译与剪辑辅助工程方案 v2.0

> 版本：2.0｜编制日期：2026-09-18｜状态：设计定稿，待实施（非上线证明）
> 依据：《视频内容提取三方向改进实施方案》1.0（2026-09-18，外部输入）＋ `docs/PROJECT_SYSTEM.md`（决策核心 V2 / P0 修复后现状）
> 取代 v1.0 设计稿。v1 中"复用已有管线 90% 基础设施""EDL 就是关键时间点列表""Netflix 级字幕"等未证实简化/宣传词按方案 §13 要求删除；本文明确**标题、概要、字幕三种处理的边界**，补时间轴与 EDL 真实契约。

## 一、目标与非目标

**目标**：
1. 信息流外文条目获得**概要级中文翻译**（含来源与状态标记），标题翻译不再替代概要翻译（B01）；
2. 视频原文/中文字幕导出（SRT/ASS）、章节结构、CMX 3600 有限子集 EDL 导出；
3. 全链路成本导向：默认只跑第一步直译，反思/意译由用户显式触发。

**非目标**（本期不做）：配音（GPT-SoVITS）、人声分离（Demucs）、WhisperX 全面替换、自动成片、成品字幕压制。
人声分离或词级对齐仅在验收样本表明现有方案精度不足后单独立项。

## 三、差距对照与概要翻译闭环（方案 §7.1 映射）

**B01 修复——处理顺序**（按内容可用度分级，不"先生成外文再翻译"双倍调用）：

1. 已有可靠中文概要：复用，`summaryOrigin=existing_chinese`；
2. 有外文概要：翻译概要与标题，保留原文，`summaryOrigin=translated`；
3. 无概要但有提取正文/转录：**直接生成中文概要**，`summaryOrigin=generated_from_content`；
4. 只有标题和 URL：可译标题，概要标记 `waiting_for_content`，**不把猜测写成已提取概要**。

ContentItem 新增可选字段（DTO 默认值兼容旧客户端，遵守工程约定 §九-4）：

```text
translatedTitle: String?        （已有）
translatedSummary: String?
sourceLanguage: String?
summaryOrigin: translated | generated_from_content | existing_chinese | unavailable
translationStatus: pending | ready | skipped | failed | waiting_for_content
translationVersion: String?
```

规则：
- 语言判定优先可信来源语言，其次轻量检测；日文假名、韩文、中英混合分别处理，**不以汉字数量为充分条件**（延续 `isForeign` 修复方向）。
- 低置信度进入可重试/人工触发路径；纯专有名词允许保持原文，记录 `skipped` 原因与有效期。
- 批量请求用对象数组 `{id,title,summary}`，返回按 ID 关联；校验缺失、重复 ID、长度、语言、数字与术语，**不靠数组顺序**。
- 外部标题、字幕和概要作为**不可信数据**输入：禁止执行其中指令，结构化结果校验限制污染。
- 首次 feed 即返回原文 + pending；客户端在可见页面按 2/5/10 秒退避刷新状态（最多 30 秒），随后显示"稍后刷新"。
- 失败最多自动重试 2 次并退避；持续失败进短期负缓存，保留手动重试入口。
- 翻译键：`hash(originalTitle + originalSummary + targetLanguage + glossaryVersion + promptVersion)`——同 ID 内容更新后必须重新处理（B04 关闭）。

## 四、字幕、章节与 EDL（方案 §7.2 映射）

**字幕**：保存不可变原始 segments，译文经 segment ID 关联；原文导出不调用翻译；中文翻译按时间相邻段组成上下文批次再映射回段落。
- SRT/ASS 校验：UTF-8、合法起止时间、排序、显式重叠处理、转义、空段处理。
- 字幕显示规范（每行字符数/最大行数/最短显示时长/阅读速度）作为**产品参数**，不引用"Netflix 级"宣传词。

**章节**：`{start, end, title, evidenceIds}`；覆盖请求区间、按时间递增、无负时长；**不把每个关键帧直接认作章节**。

**EDL 首版 = CMX 3600 有限子集**：单视频轨、直切，含 reel、源入出点、序列入出点、帧率、DF/NDF。
- 可变帧率媒体先生成恒定帧率代理并保存映射，或**明确拒绝精确 EDL**——不输出看似可用但时间错位的文件。
- 元数据时长未知时禁止精确剪辑导出，其他能力降级并警告（B07 联动）。
- 导出端点以 taskId 关联持久证据与产物；过期返回明确状态。

## 五、自动执行范围（与主方案"全字幕翻译由显式请求触发"对齐，消除 v2.0 初稿冲突）

| 用户行为 | 允许自动执行 |
|---|---|
| 浏览信息流 | 标题及概要处理（四分支 §三：复用/翻译/生成/waiting_for_content）——**唯一自动步骤** |
| 打开字幕编辑器 | 仅加载已有字幕与翻译状态，不触发新模型调用 |
| 点击「翻译字幕」 | 全字幕翻译（时间相邻段上下文批次直译） |
| 点击「优化译文」 | 反思（挑术语/人名/数字疑点）+ 意译润色（长视频升 Gemini 长上下文），执行前预算检查 |

三步分级保留为成本档位语义：直译（豆包链首级）→ 反思（疑点挑错）→ 意译（上下文润色），**只有直译中的"标题+概要"部分随信息流自动执行**，字幕级直译与反思/意译全部由上表显式动作触发。

术语库 `data/glossary.json` 注入翻译 prompt 保跨视频一致；冷启动从 preferenceSummary 抽取领域术语。`glossaryVersion` 进翻译缓存键。

## 六、共享依赖

共用内核组件（SourceResolver/AnalysisPlanner/ProcessRunner/TranscriptService/EvidenceService/ArtifactCache/BudgetService/ExportService），详见方向 A §六。ExportService 职责：SRT/ASS、章节、EDL 格式输出——**不把时间点列表直接称为 EDL**。

## 七、缓存和费用

- 真正容量控制：内存 LRU 热缓存上限 2000 条 + 落盘（现有 `translations.json` 结构无内容哈希，**不能直接视为新缓存可靠命中**：保存备份，有原文校验时迁移，否则自然重建）。
- 队列有界：翻译队列初值 200、批大小上限 20、限输入 token；满时返回可重试状态。
- 同一阶段键只允许一个在途任务（扩展现有 in-flight 机制为阶段级）。
- 费用：重试计入总口径；数字、单位、否定含义、专有名词为质量验收重点；缓存命中后不再发生模型调用。

## 八、任务清单（映射方案 §9：M3 概要翻译闭环 + M6 字幕剪辑，M6 依赖 M2/M3/M4 契约）

| 任务 | 内容 | 完成定义 |
|---|---|---|
| C-1 | ContentItem 概要字段 + 状态机 | 序列化兼容；旧客户端回归通过 |
| C-2 | 概要翻译处理顺序四分支 | `waiting_for_content` 不伪装成概要 |
| C-3 | 内容键缓存 + 在途合并 | 同 ID 内容更新后旧译文不复用 |
| C-4 | 客户端展示：概要译文、原文切换、状态刷新 | 2/5/10s 退避，30s 后"稍后刷新" |
| C-5 | SRT/ASS 导出 + 结构校验 | 原文/中文分别导出可播放 |
| C-6 | 章节结构化 + 客户端复制按钮 | 覆盖区间校验通过 |
| C-7 | CMX 3600 EDL 导出 | 至少一个目标剪辑软件实际导入成功 |

## 九、验收数据

- ≥40 条外文/混合条目（含英语、日语、韩语、中英混合、纯专有名词、内容更新）：可翻译条目召回率 ≥95%，中文误触发率 ≤5%。
- 概要人工检查通过率 ≥90%；测试集中数字、单位、否定含义无未修复关键错误。
- 同批 10 并发请求单批模型翻译只执行一次；超 20 条自动分批完成，无需额外 feed 请求推动（B04 回归；`TranslationServiceTest` 五场景已作为服务端单测基线，2026-09-21 通过）。
- ≥10 个视频字幕通过结构校验并可播放：时间误差中位 ≤0.5s、P95 ≤1.5s，不满足的来源标记质量受限。
- EDL 实际导入验证素材匹配、起止帧和序列长度；**只通过文本解析不算完成**。

## 十、限制

- **当前来源仅 HTTP(S) 媒体直链**（服务端下载器 `http.get(url)` 无平台页解析器）；YouTube/Bilibili 平台页解析器落地并样本验证后才开放。登录/DRM/区域限制明确报错。
- 字幕时间轴依赖共享内核真实时长校正（B07）落地；时长未知来源的剪辑导出被禁用。
- 旧 `translations.json` 无内容哈希，迁移期可能 miss（重建而非错误命中）；现缓存为落盘截断（MAX_ENTRIES=2000），**真实 LRU 与内存容量控制未实现（B05 未关闭）**。

## 十一、发布与回滚

- 功能开关：`summaryTranslation`、`editingExports`（ConfigStore Snapshot + 环境变量 + 默认 false，同 `decisionCoreV2` 灰度先例）。
- 部署顺序：先部署可兼容旧客户端的服务端（新字段可选），再部署新客户端；回滚保留新缓存与产物，不做破坏性数据降级。
- 灰度与自动回滚阈值沿用方案 §12（错误率 +5pct / 费用中位数 +20% / 概要事实错误聚集触发）。
